2026-09-29. Software implemented at `ebf781c0ad12d3934dc250ef1ea10a312079e897`. Complete live backfill and
metadata acceptance remain open; neither partial catalogs nor offline tests
satisfy them. The final [ledger](../COVERAGE_LEDGER.md) records the actual cohort.

Catalog pages use `show=all`, zero-based pages of 100 and an empty terminal
page. Durable page/cycle/member progress survives collector restart. Partial,
repeated or changing enumerations stay partial and never remove hosting routes.
Sources rotate fairly, and exhausted task quotas defer pending batches so large
metadata queues cannot hide catalog work. Candidate work has reserved capacity.
The unchanged limits are four global requests, one/origin, one-second spacing,
15-second timeout, 16 MiB decoded body, 300 requests/source/hour, 20 other-subject
inventories/hour, 40 unresolved metadata attempts/hour, hourly inventories,
12-hour catalogs and 24-hour metadata TTL. Budgets persist in SQLite.

Metadata selection retains source variants and deterministic priority. Catalog
success defers corresponding individual jobs to their TTL; cached no-ops neither
make HTTP requests nor report a new upstream success or clear a source error.
Entity 404s affect that job rather than pausing all source intake. Observer
identity mismatch still pauses the source. Quarantine never publishes private
IDs or drives outbound enrichment. Original user config/database remain intact.
New migrations have verified pre-migration backups; applied SQL was not edited.

Independent `source:enumerate` runs preserve normalized member/hash records
without publishing application data. Reports distinguish missing references,
partial/moving sets and complete bounded references, with timing, schema,
consecutive differences, omission counts and unknown percentages. JSON/Markdown
reports include revision, public-only configuration fingerprint, UTC window,
source contributions, hosting versus metadata-only counts, topology, queues,
metadata and freshness. They do not estimate global network coverage.

## Performance correction and validation

A real large snapshot exposed an expensive publication lookup: 15.3 ms per RID
in a 25-RID query sample, with a multi-minute event-loop stall and an internal
collector lease failure. The failed run is retained locally rather than presented
as passing. Revision `692c3f08af36977ecad80dc366e5443989c148e7` uses the equivalent
indexed eligible-evidence lookup, measured at 0.004 ms per RID. Offline replay
of an actual 15,913-row saved snapshot took 1.5 seconds with unchanged aggregate
counts. That replay is performance evidence, not new live coverage. A subsequent
60-second actual collection finished without the internal failure; Rosa source
errors remained visible. Final revision adds cached-metadata accounting regression.

files**. Tests cover repeated-page/resume behavior, fairness after exhausted
