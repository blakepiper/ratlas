Audit findings:

- `enqueueDiscovery` selects subjects from `eligible_routes`, and execution
  checks the same view. A configured observer without an edge cannot bootstrap
  third-party discovery. Add a separate bounded public candidate store.
- Catalog intake starts at page zero after every budget deferral. Persist page
  progress and detect repeated/moving pages; metadata catalogs never reconcile
  route absence.
- Budgets persist in SQLite and origin spacing is shared; the collector has
  one writer lease and the API is read-only. Priority ordering can let a long
  catalog hold the source slot; bounded page jobs must yield to other work.
- Header repository counts include metadata-only records. Coverage breadth
  must separately count RIDs with eligible hosting evidence, metadata-only
  RIDs, and historical `all` pairs, using the existing window semantics.
- Source health has a heartbeat but reports saved healthy reads as healthy
  even after collector exit. Expose collector running/stopped/stale separately.

Acceptance queries use the existing public views: 24h/7d require present routes
with `last_positive_at` in the window; `all` includes retained positive evidence,
including subsequently missing pairs. Group subjects and hosting pairs distinctly.
Evaluate source contributions against the union of other sources, keep observer
identity separate from subject identity, and never expose quarantine IDs.
Reference enumeration denominators remain unknown until independently completed.
