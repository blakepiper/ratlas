## What works

CLI NDJSON and pinned HTTP adapters, durable jobs and request budgets, source-specific
metadata, staged snapshot reconciliation, event intake/replay, reconnect/backoff,
coverage gaps and owned-child cleanup are implemented and fixture-tested. HTTP
transport checks use an explicitly created loopback fixture; CLI tests use temporary
synthetic executables. Neither is evidence of live Radicle compatibility.

All specified read-only API routes are present: search/filter/pagination, random
repository, repository and node details, source-aware relationship navigation,
bounded graph projections, normalized activity, hourly summary queries and sanitized
source health. Publication gates cover every endpoint. Weak ETags include the window
bucket, so observation expiry changes visible data even without collector writes.
The existing React screen uses this API and adds a source coverage readout.

The deterministic demo has 100 RIDs, 20 node identities, 300 distinct hosting
relationships, two sources, 20 unresolved names and two source-state disagreements.
The report demonstrates three seeders backed by six evidence records for one RID.
A separate failed-snapshot fixture keeps all 100 repositories and 300 relationships.
No failure is injected into a live database or Radicle node.

Full search/filter/detail controls, the interactive graph, the final activity/coverage
interface and maintenance work remain at later checkpoints. The release checklist
remains pending final validation; the specification's stage checkboxes now track
actual completion, with the live smoke test unchecked.

## Validation results

- Final `nix develop --command pnpm check`: passed formatting, ESLint and repository/
  Firefox policy checks, workspace/tool typechecks, **51 deterministic tests**, both
  Firefox viewport tests and production build. E2E uses the built production SPA,
  real isolated SQLite data and an ephemeral local API port.
- `pnpm doctor --config config/ratlas.demo.json`: passed native SQLite 3.53.4,
  FTS5, WAL/read-only reader/reopen, current demo schema and isolated headless Firefox
  148.0.2. The selected bundle remains Firefox-only; Playwright is 1.59.1.
- `pnpm data:review --config config/ratlas.demo.json`: generated actual counts,
  provenance, disagreement, missing-name, failure-preservation and query-plan evidence.
- Actual `pnpm demo` startup: summary and source coverage verified through Vite's
  proxy; SIGTERM cleaned up owned processes and closed ports 3000/5173.
- `pnpm collect:once --config config/ratlas.example.json` and
  `pnpm test:live --config config/ratlas.example.json`: both returned **2**, correctly
  reporting missing configured sources. These are prerequisite results, not live passes.
- Transport regressions cover compressed decoded-body limits, redirects without
  following, HTML/malformed JSON, 404/429/5xx, retry headers and private/reserved DNS
  answers. Subprocess regressions cover initial snapshot/event races, EOF/reconnect,
  preserved reconciliation requests, quiet streams and subscriber cleanup.
- Durable intake/leases, source budgets, breaker opening, shutdown/restart eligibility,
  interrupted snapshots, replay, quarantine, API traversal, stable filtering, graph
  limits/edge integrity and clock-driven cache expiry have deterministic checks.

Intermediate tests found and fixed unread HTTP-body abort errors, a skipped first
one-shot CLI snapshot, reconnect-request loss during a snapshot and shutdown being
negative-cached as an upstream failure. Final checks pass without weakened assertions.
Vite still emits harmless upstream Zod comment-annotation warnings; the build succeeds.
