The map now uses actual filtered repository–hosting-node observations. It offers
a deterministic bounded overview, selected one-hop neighborhoods, and a full
view when the requested 25,000-vertex/150,000-edge limits permit it. Counts
show displayed versus eligible entities and relationships separately from the
hub display filter. Selection follows the catalog and detail panels, and a
repository can lead through a hosting node to its other observed repositories.
The Sigma canvas and timed ForceAtlas2 worker are implemented with deterministic
positions, reduced-motion handling, controls, and cleanup. When WebGL is
unavailable, the accessible map entity list opens and the catalog/detail
workflow remains usable.

For the small fixture, run `env -u TMPDIR nix develop --command pnpm demo` and
open http://127.0.0.1:5173 in Firefox. For the target fixture, run
`env -u TMPDIR nix develop --command pnpm demo --dataset target` at the same
URL. The latter creates `.ratlas/demo/target.sqlite` when it is missing; the
checked target database is already present locally and ignored by Git. Both
commands run no collector. Existing demo processes currently occupy ports
3000/5173 and were left untouched, so their owner must stop them before
restarting either fixture. The existing small-demo Vite page may already be
open at that URL. A separate target-scale production-style API was started on

The final `pnpm check` passed: formatting, lint, Firefox-only and repository
policy checks, types, 52 deterministic tests, 18 desktop/narrow Firefox UI
tests, and production build. Two real WebGL context-loss cases were skipped
because neither test viewport produced a canvas. The explicit no-WebGL test,
fallback entity navigation, hub hiding, full-mode limit explanation, API
no-dangling-edge contracts, and target database preparation passed. Browser
tests used isolated Nix-provided Playwright Firefox 148.0.2; no user Firefox
profile was accessed. Headless and headed runs both reached the fallback. The
headed desktop check reported `webglContext=false`, `renderer=null`, and
`graphRenderer=fallback`; hardware/software WebGL cannot be classified. The
required headed project command is
`nix develop --command pnpm exec playwright test --project=firefox-desktop --headed`.
The targeted headed context-loss case was skipped for the same reason.
Canvas clicks, actual pan/zoom, layout timing, and repeated-navigation worker
cleanup remain unverified. The graph-rendering prerequisite is therefore
**blocked**, as required by the specification; fallback success is not counted
as a rendered graph.

Initial target-scale measurements were made on an x86_64 Intel Core Ultra 7
258V machine with eight cores and 30 GiB RAM, Node 24.21.0, SQLite 3.53.4,
Playwright 1.59.1, and Firefox 148.0.2. Mulberry32 seed `20260925` produced
exactly 20,000 repositories, 2,000 node identities, 100,000 distinct hosting
relationships, four overlapping sources, and 2,000 unresolved names. The
synthetic generation command reported 12.629 seconds; the database was
163,319,808 bytes. These are local initial samples, not the 20-warm-up/200-run
concurrency benchmark scheduled for Stage F:

| Direct read-only database call          |                  Elapsed | JSON bytes | Result                                           |
| --------------------------------------- | -----------------------: | ---------: | ------------------------------------------------ |
| Summary                                 |                 1,081 ms |      2,742 | 20,000 repos / 100,000 relationships             |
| Catalog, `q=synthetic`, first 25        |                   778 ms |      7,389 | 25 results                                       |
| Bounded overview, three sequential runs | 1,219 / 1,107 / 1,114 ms |  1,053,741 | 2,000 of 22,000 vertices; 2,766 of 100,000 edges |

Single-query times are higher than the 250 ms warm-p95 engineering target,
though this small sample cannot establish a p95. In isolated **headless fallback**
Firefox, elapsed time from navigation to visible bounded counts and fallback
was 5,138 ms desktop and 5,088 ms narrow. These timings include page and API
loading and say nothing about a real Sigma first render or frame rate. No
headless/hardware timing samples were mixed.
