## Measured API performance

A read-only benchmark at 21:54:06 UTC measured the actual 15,918-RID dataset,
29,335 pairs and 6,215 usable names at that time, Node 24.18.0/SQLite 3.53.4,
20 samples after three warmups at concurrency one and four. The application
has subsequently reached 6,315 names; no scale change is inferred from that.

| Case                            | First request ms | Warm p95 c1 ms | Warm p95 c4 ms |
| ------------------------------- | ---------------- | -------------- | -------------- |
| summary                         | 457.4            | 0.49           | 0.77           |
| bounded graph                   | 523.8            | 6.49           | 23.89          |
| repeated catalog search         | 5.00             | 0.31           | 0.99           |
| five varied broad catalog terms | 0.29             | 0.41           | 2.73           |
| distinct exact RID searches     | 1.23             | 1.19           | 4.35           |
| distinct neighborhoods          | 3.45             | 1.90           | 6.63           |

These are Fastify injection measurements with read-only SQLite, not network,
Firefox layout or frame timing. Repeated queries use bounded caches; distinct
text searches often have empty results and cannot represent broad result-heavy
queries. Cold summary/graph still exceed the 250 ms warm-query budget. Existing
graph edge/neighborhood/payload limits were retained. A separate benchmark during
actual backfill preserved warm API responsiveness; neither test proves day-long
load behavior. Evidence: `.ratlas/reports/benchmark-live.json`,
`.ratlas/coverage/final-benchmark.log` and `benchmark-during-backfill.log`.
